# Quant Platform 部署手册（Linux）

> 适用环境：Ubuntu 22.04/24.04 或 CentOS Stream 9 / RHEL 9 等 systemd Linux 发行版。
> 本文档覆盖：第三方依赖安装 → 源码打包 → 数据库初始化 → 项目配置 → Web 服务器（Nginx）部署 → 后端服务运行 → 验证排错。
> 不涉及 Windows / macOS，也不涉及微信小程序端的打包（小程序走微信开发者工具上传）。

---

## 1. 架构与组件一览

| 组件 | 角色 | 关键参数 |
|------|------|----------|
| `stock-service` | 主后端（因子/策略/回测/推荐/监控/AI） | 端口 **8080**，context-path **`/api`**，可执行 jar：`stock-service/target/stock-service-1.0.0.jar` |
| `backend-mp` | 小程序后端（推荐/监控接口） | 端口 **8082**，context-path **`/api`**，路径前缀 **`/mp`**，jar：`backend-mp/target/backend-mp-1.0.0.jar` |
| `frontend` | React 18 + Vite + Ant Design 前端 | `npm run build` 产物目录 **`frontend/build`**（注意不是 `dist`），由 Nginx 托管 |
| MySQL 8.0 | 元数据存储（策略/配置/财务/用户） | 数据库名 **`stock`** |
| ClickHouse 24.x | 时序/列存（因子值、日线、资金流） | 数据库名 **`stock`**，HTTP 端口 **8123**，原生端口 9000 |
| Nginx | 静态资源托管 + 反向代理 | 监听 80/443，按路径分流到两个后端 |
| Python 3.11+ | 行情/财务数据采集脚本 | `stock-service/scripts/*.py` |

> 路由约定（已在代码层固定，**勿随意更改**）：
> - `stock-service`：监听 8080，所有接口以 `/api` 为前缀；健康检查 `/api/actuator/health`
> - `backend-mp`：监听 8082，接口以 `/api/mp` 为前缀
> - WebSocket(STOMP)：`/api/ws` 与 `/api/ws-native`
> - Nginx 分流：`/api/mp/**` → backend-mp(8082)，其余 `/api/**` → stock-service(8080)

## 2. 安装第三方依赖（Linux）

### 2.1 基础工具
```bash
# Debian/Ubuntu
sudo apt-get update
sudo apt-get install -y git curl wget unzip tar ca-certificates gnupg lsb-release fontconfig

# RHEL/CentOS Stream
sudo dnf install -y git curl wget unzip tar ca-certificates
```

### 2.2 JDK 21（后端运行 + 编译）
```bash
# Debian/Ubuntu 24.04 自带 openjdk-21
sudo apt-get install -y openjdk-21-jdk

# 其他发行版用 Eclipse Temurin 21
# 下载通用 tarball 后解压到 /opt 并配置 JAVA_HOME 即可
# https://adoptium.net/temurin/releases/?version=21
```
验证：`java -version` 应输出 21.x。设 `JAVA_HOME`（建议写入 `/etc/profile.d/java.sh`）：
```bash
export JAVA_HOME=$(dirname $(dirname $(readlink -f $(which java))))
```

### 2.3 Maven 3.9（后端打包）
```bash
# 通用方案：下载 apache-maven-3.9.x-bin.tar.gz 解压到 /opt
# https://maven.apache.org/download.cgi
```
或 Ubuntu：`sudo apt-get install -y maven`（版本可能偏旧，建议用官方 tarball 保证 3.9+）。

### 2.4 Node.js 18+（前端打包；推荐 20 LTS）
```bash
# NodeSource 仓库（Debian/Ubuntu）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# RHEL/CentOS
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
sudo dnf install -y nodejs
```
验证：`node -v`（≥18）、`npm -v`。

### 2.5 MySQL 8.0
```bash
# Debian/Ubuntu
sudo apt-get install -y mysql-server
sudo systemctl enable --now mysql

# RHEL/CentOS（使用 MySQL 官方或系统 mariadb 替代均可，需 8.0 兼容）
# 建议：https://dev.mysql.com/downloads/repo/yum/
```
首次初始化后设置 root 密码并创建应用库与账号：
```bash
sudo mysql -u root <<'SQL'
CREATE DATABASE stock CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'quant'@'%' IDENTIFIED BY '更换为强密码';
GRANT ALL PRIVILEGES ON stock.* TO 'quant'@'%';
FLUSH PRIVILEGES;
SQL
```

### 2.6 ClickHouse 24.x
```bash
# 官方一键安装（含 server + client）
curl https://clickhouse.com/ | sh
sudo ./clickhouse install
sudo systemctl enable --now clickhouse-server
```
设置 default 用户密码（编辑 `/etc/clickhouse-server/users.xml` 的 `<default><password>` 或直接用 SQL）：
```bash
clickhouse-client --query "ALTER USER default IDENTIFIED BY '更换为强密码'"
```
创建数据库：
```bash
clickhouse-client --query "CREATE DATABASE IF NOT EXISTS stock"
```

### 2.7 Nginx（Web 服务器）
```bash
# Debian/Ubuntu
sudo apt-get install -y nginx
sudo systemctl enable --now nginx

# RHEL/CentOS
sudo dnf install -y nginx
sudo systemctl enable --now nginx
```

### 2.8 Python 3.11+（数据采集脚本，可选但推荐）
```bash
# Ubuntu 24.04
sudo apt-get install -y python3 python3-pip python3-venv

# 若需 3.13（README 推荐）：Ubuntu 用 deadsnakes PPA，或 pyenv 安装
```
建议为采集脚本建独立 venv 并安装依赖（脚本目录 `stock-service/scripts`，依赖见脚本内 import）：
```bash
python3 -m venv /opt/quant-platform/pyenv
/opt/quant-platform/pyenv/bin/pip install pymysql requests pandas
```

### 2.9 Redis（可选）
`docker-compose.yml` 提供了 redis 服务，但 `stock-service` 当前未配置 Redis 客户端（限流用 Bucket4j 内存实现），**生产非必须**。如需启用请在应用配置中显式接入后再部署。

## 4. 打包

### 4.1 后端（Maven 多模块）
父 POM 模块：`common` → `platform-core` → `stock-service` / `backend-mp`。
```bash
cd /opt/quant-platform
# -am 同时构建依赖模块；-DskipTests 跳过测试（CI 中另跑）
mvn -pl stock-service,backend-mp -am clean package -DskipTests
```
产物：
- `stock-service/target/stock-service-1.0.0.jar`
- `backend-mp/target/backend-mp-1.0.0.jar`

> 注意：本项目 **前端不是 Maven 模块**，需单独用 npm 构建（见 4.2）。

### 4.2 前端（Vite）
```bash
cd /opt/quant-platform/frontend
npm install            # 安装依赖（首次或 package.json 变更时）
npm run build          # 产物输出到 frontend/build
```
`vite.config.js` 中 `build.outDir` 为 `build`，因此产物目录是 `frontend/build`（不是 `dist`）。

> 应用启动**不执行任何 DDL**，必须手动导入表结构脚本。

## 6. 配置项目（环境变量）

生产配置通过环境变量注入（`application-prod.yml` 无开发默认值，缺省会 fail-fast）。
两个后端各自读取不同的变量集合。

### 6.1 stock-service 必需/常用环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `SPRING_PROFILES_ACTIVE` | 固定 `prod` | — |
| `MYSQL_HOST` | MySQL 地址 | 无（必填） |
| `MYSQL_PORT` | MySQL 端口 | 无（必填） |
| `MYSQL_DATABASE` | 库名，须为 `stock` | 无（必填） |
| `MYSQL_USER` | 账号 | 无（必填） |
| `MYSQL_PASSWORD` | 密码 | 无（必填） |
| `CLICKHOUSE_HOST` | ClickHouse 地址 | 无（必填） |
| `CLICKHOUSE_PORT` | CH HTTP 端口 | `8123` |
| `CLICKHOUSE_DATABASE` | CH 库名，须为 `stock` | `stock` |
| `CLICKHOUSE_USER` | CH 账号 | `default` |
| `CLICKHOUSE_PASSWORD` | CH 密码 | 无（必填） |
| `CORS_ALLOWED_ORIGINS` | 前端域名，逗号分隔 | 无（必填，prod 强制） |
| `CREDENTIAL_AES_KEY` | 凭证加密主密钥（32 字节十六进制） | 空（prod 建议必填） |
| `SA_TOKEN_COOKIE_SECURE` | HTTPS 下设 `true` | `false` |
| `LLM_API_KEY` | DeepSeek 等大模型 Key（启用 AI 分析时填） | 空（可选） |
| `LLM_BASE_URL` / `LLM_MODEL` | 模型网关地址/模型名 | deepseek 默认 |

可直接用仓库提供的模板 `deployment/quant-platform.env.example`（复制到 `/opt/quant-platform/stock-service/quant-platform.env` 后改值）。

### 6.2 backend-mp 配置
`backend-mp/src/main/resources/application-prod.yml` 中 **MySQL 连接已硬编码**为
`jdbc:mysql://127.0.0.1:3306/stock`，账号 `admin` / 密码 `Hanlu@123`。
因此 backend-mp 必须连到 localhost 上名为 `stock` 的 MySQL，且存在 `admin` 账号；或部署前直接修改该 yml 后重新打包。
小程序相关变量（可用环境变量覆盖 yml 中的字面值）：

| 变量 | 说明 |
|------|------|
| `MP_TOKEN` | 小程序后端访问令牌，默认 `quant-mp-2026-secret` |
| `WECHAT_MINI_APPID` / `WECHAT_MINI_SECRET` | 微信小程序 AppID / Secret |

### 6.3 配置文件位置
- 公共/基础配置：`stock-service/src/main/resources/application.yml`
- 生产配置：`stock-service/src/main/resources/application-prod.yml`、`backend-mp/src/main/resources/application-prod.yml`
- 启动方式：
  ```bash
  java -jar stock-service-1.0.0.jar --spring.profiles.active=prod
  java -jar backend-mp-1.0.0.jar  --spring.profiles.active=prod
  ```

## 7. 部署 Web 服务器（Nginx）

### 7.1 放置前端产物
```bash
sudo mkdir -p /var/www/quant-platform
sudo cp -r /opt/quant-platform/frontend/build/* /var/www/quant-platform/
# 后续前端发版只需重新 cp 并无需重启 nginx（SPA 缓存可顺带清）
```

### 7.2 配置 Nginx
仓库已提供模板 `deployment/nginx.conf`（含安全头、gzip、限流、WebSocket upgrade、SPA 回退）。
部署步骤：
```bash
# 复制到 conf.d（该目录在 http 上下文中被 include，limit_req_zone 合法）
sudo cp /opt/quant-platform/deployment/nginx.conf /etc/nginx/conf.d/quant-platform.conf
sudo nginx -t        # 语法检查
sudo systemctl reload nginx
```
部署前在 `quant-platform.conf` 中替换：
1. `server_name your.domain.com;` → 你的域名（或多域名/下划线 `_`）
2. `root /var/www/quant-platform;` 已指向前端产物目录（如改动请同步）
3. 启用 HTTPS：取消 `listen 443 ssl;` 段并填证书路径；取消 `Strict-Transport-Security` 与 `return 301 https://...` 注释
4. `upstream` 中 `127.0.0.1` 若后端在其它主机/容器，改为对应地址（保持 8080 / 8082 端口）

> 反向代理规则（已在模板中写好，勿改路径前缀）：
> - `location /api/mp/` → backend-mp(8082)
> - `location /api/` → stock-service(8080)，带 `limit_req` 限流
> - `location /api/ws`、`/api/ws-native` → stock-service，带 WebSocket upgrade

### 7.3 防火墙
仅对外暴露 80/443；后端 8080/8082、MySQL 3306、CH 8123/9000 只对内网/本机开放。
```bash
sudo ufw allow 80,443/tcp
# 切勿 ufw allow 3306 / 8123 / 9000 对公网
```

## 8. 运行后端服务（systemd）

为两个后端各建一个 systemd 单元，实现开机自启、崩溃重启、日志归集。
仓库提供模板：`deployment/quant-stock.service`、`deployment/quant-mp.service`。
部署：
```bash
sudo cp /opt/quant-platform/deployment/quant-stock.service /etc/systemd/system/
sudo cp /opt/quant-platform/deployment/quant-mp.service   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now quant-stock quant-mp
sudo systemctl status quant-stock quant-mp
```
单元要点：
- `EnvironmentFile=/opt/quant-platform/stock-service/quant-platform.env`（stock-service 读取）
- `WorkingDirectory` 指向 jar 所在目录
- `Restart=on-failure`，`User=quant`（非 root 运行，需 `chown -R quant /opt/quant-platform`）
- 日志：`journalctl -u quant-stock -f`

## 9. Docker 部署（可选，同样适用 Linux）

仓库提供 `Dockerfile` 与 `docker-compose.yml`，可一键拉起 MySQL + ClickHouse + Redis + 应用。
注意点：
- **`Dockerfile` 当前只构建 `stock-service`**（镜像内仅 `app.jar`，不含 backend-mp 与前端）。若需完整栈，请补充多阶段构建或分别打镜像。
- `docker-compose.yml` 中 `MYSQL_DATABASE=quant_platform`，与代码实际库名 **`stock`** 不一致，启动前请改为 `stock`（或统一命名）。
- 前端仍需在宿主机用 Nginx 托管（见第 7 节），或另行构建前端镜像。

```bash
cd /opt/quant-platform
# 按需编辑 docker-compose.yml 的密码/库名
docker compose up -d --build
docker compose ps
```

## 10. 验证与排错

### 10.1 健康检查
```bash
curl -f http://127.0.0.1:8080/api/actuator/health   # 应返回 {"status":"UP"}
curl -f http://127.0.0.1/api/actuator/health         # 经 Nginx 也应 200
curl -I  http://<域名>/                                # 前端首页 200，且含 index.html
```

### 10.2 常见故障
| 现象 | 原因 | 处理 |
|------|------|------|
| stock-service 启动即退出，报缺少必需属性 | 环境变量未注入（MYSQL_*/CLICKHOUSE_*/CORS_ALLOWED_ORIGINS） | 检查 `EnvironmentFile` 路径与 `systemctl show quant-stock -p EnvironmentFile` |
| `/api/mp/**` 502 | backend-mp 未起或端口错 | `systemctl status quant-mp`、`ss -ltnp | grep 8082` |
| 前端白屏/刷新 404 | Nginx 未配 SPA 回退 | 确认 `location / { try_files $uri $uri/ /index.html; }` |
| ClickHouse 连接拒绝 | 端口/密码错或 CH 未起 | 用 `clickhouse-client` 自测；确认 JDBC 走 HTTP 8123 |
| CORS 报错 | `CORS_ALLOWED_ORIGINS` 未含前端域名 | 改环境变量后重启 stock-service |
| HTTPS 下登录态丢失 | `SA_TOKEN_COOKIE_SECURE` 未设 `true` | 设 `true` 并重启 |

### 10.3 日志
```bash
journalctl -u quant-stock -n 200 -f
journalctl -u quant-mp   -n 200 -f
sudo tail -f /var/log/nginx/error.log
```
