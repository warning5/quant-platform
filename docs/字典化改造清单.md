# 字典化改造清单（可纳入字典管理的全部硬编码项）

> 扫描时间：2026-08-01
> 扫描范围：frontend/src 全部页面 + backend 全部 Java
> 目标：把所有"状态/类型/选项"硬编码常量改为读字典（sys_dict_data），实现"同类型新增枚举 = 纯数据操作，业务零改码"。
> 改造分两类：
> - **A 类（纯前端）**：仅标签/颜色/下拉选项，改为 `useDict(type)` 即可，无后端逻辑。
> - **B 类（含后端逻辑）**：后端有 `CASE WHEN`/排序/分支依赖枚举值，必须同步改 SQL/Service 读字典属性（sort/ext_json）。

## 优先级与实施建议

### P1（建议首批做，高价值）
- **理由**：跨多页面重复 + 命名不一致（FACTOR/STRATEGY/BACKTEST 状态各自一套），且 `SLA_SEVERITY`/`TASK_TRIGGER_TYPE`/`NOTIFY_CHANNEL`/`MENU_TYPE` 有后端逻辑依赖。
- 项：`SLA_SEVERITY`(3)、`TASK_STATUS`(1)、`TASK_TRIGGER_TYPE`(2)、`FACTOR_STATUS`(4)、`STRATEGY_STATUS`(6)、`BACKTEST_STATUS`(9)、`NOTIFY_CHANNEL`(33)、`MENU_TYPE`(29)
- 其中 `SLA_SEVERITY` 必须改后端 `CASE WHEN`（B 类），其余多为 A 类前端改造。

### P2（第二批，纯前端展示 + 运营可配置）
- 选股 6 套(10–15)、滚动回测(16–19)、财务/研报/分析(20–22)、LLM(23–24)、MARKET(30)、DATA_QUALITY(31)、SECTOR_CATEGORY(32)

### P3（远期，低频单页）
- 推荐(25–26)、实盘事件(27–28)

## 实施路径（推荐）
1. **建字典框架**：`sys_dict_type` + `sys_dict_data`(value/label/sort/color/ext_json/enabled) + `DictController` + `DictService`(带缓存 evict，参考 `NotificationConfigService`) + 前端 `useDict(type)` hook + 字典管理页面。
2. **首批接入 P1**：先把 8 个 P1 字典类型种子化（含 `SLA_SEVERITY` 的 `sort`），改造前端常量 + 后端 `CASE WHEN`（#3）和 `menu_type` 过滤(#29)。
3. **滚动接入 P2/P3**：逐页面把 `XXX_LABELS/COLORS/OPTIONS` 改为 `useDict`，删硬编码常量。
4. **铁律**：业务代码改为"遍历字典列表 + 读属性"，禁止 `switch(value){case A...}` 枚举全部可能，保证新枚举值透明不崩。

> 注：以上全部为前端 `*.jsx/*.js` 内的常量与少量后端 `CASE WHEN`；后端字符串枚举（如 `triggerType`、`notification channel`）目前以字面量散落，纳入字典后由字典值约束，不改不改业务分支逻辑（除非新值带来新行为）。
