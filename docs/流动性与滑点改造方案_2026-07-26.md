## ① 回测引擎：启用 VOLUME 滑点 + 加容量约束

### 1.1 现状（代码证据）
| 位置 | 现状 |
|---|---|
| `BacktestEngine.java:216` | `slippageModel` 默认 `"FIXED"`（固定比例） |
| `BacktestEngine.java:1562-1571` | `applySlippage` 已有 VOLUME 模型：`slip = baseRate × (1 + sqrt(tradeAmount/dayAmount) × 10)`，但仅当 model=VOLUME 才走 |
| 调用点 | `:444 / :505 / :927 / :1800 / :1838`，`dayAmount = bar.getAmount() × 1000`（千元→元） |
| 容量约束 | **无**。可假设任意成交量内成交，VOLUME 只加滑点不拦单 |

### 1.2 改造清单

**A. 默认改 VOLUME（一行）**
```java
// BacktestEngine.java:216  改前
String slippageModel = task.getSlippageModel() != null ? task.getSlippageModel() : "FIXED";
// 改后
String slippageModel = task.getSlippageModel() != null ? task.getSlippageModel() : "VOLUME";
```
> 保留 task 级可配：显式传 FIXED 仍可用。

**B. VOLUME 系数提取为常量（避免硬编码 ×10）**
```java
// 新增类常量
private static final double VOLUME_IMPACT_COEFF = 10.0; // 冲击系数，可调
// applySlippage 内
slip = baseSlippage * (1 + Math.sqrt(ratio) * VOLUME_IMPACT_COEFF);
```

**C. 加容量约束（核心缺口）**
新增私有方法，在 5 个调用点 `applySlippage` **之前**插入：
```java
private static final double MAX_PARTICIPATION = 0.08; // 复刻模拟盘 8% 规则

/** 单笔成交金额不得超过当日成交额 MAX_PARTICIPATION，否则按比例缩股 */
private long scaleToCapacity(long shares, double price, MarketDailyBar bar) {
    double dayAmount = bar.getAmount() != null ? bar.getAmount().doubleValue() * 1000 : 0;
    if (dayAmount <= 0) return shares;
    double maxAmount = dayAmount * MAX_PARTICIPATION;
    long maxShares = (long) (maxAmount / price);
    return Math.min(shares, Math.max(100, maxShares));
}
```
调用点示例（以 :444 为例，其余 4 处同构）：
```java
// 改前
double dayAmount = bar.getAmount() != null ? bar.getAmount().doubleValue() * 1000 : 0;
double price = applySlippage(execPrice, false, slippage, amount, dayAmount, slippageModel);
// 改后：先缩股再算滑点
shares = scaleToCapacity(shares, execPrice, bar);
amount = shares * execPrice;
double dayAmount = bar.getAmount() != null ? bar.getAmount().doubleValue() * 1000 : 0;
double price = applySlippage(execPrice, false, slippage, amount, dayAmount, slippageModel);
```

### 1.3 验证
- 单只小成交量大单（如买某日成交额 1% 的票）→ 改后滑点随参与率上升；买 20% 日成交额 → 自动缩到 8% 且滑点封顶。
- 与 `PaperTradingService:952` 的 8% 逻辑口径一致，回测/模拟盘对齐。

### 1.4 风险/回滚
- 默认改 VOLUME 会使所有未显式配置的回测收益**下调**（更真实，但数字变小）。属预期改善，非回归。
- 回滚：把 :216 改回 `"FIXED"` 即可。

| 选股质量分（`RecommendationService:3284`） | 已含"日均成交额+换手率适中度"打分 → 前端已挡极端换手，但**组合层无硬上限** |

### 2.2 改造清单

**A. 新增常量**
```java
// 流动性阈值（20日均值口径，从 CH stock_daily 取）
private static final double ILLIQUID_AVG_TURNOVER_PCT = 1.0;   // 20日平均换手<1% 视为低流动性
private static final double ILLIQUID_MIN_AVG_AMOUNT_WAN = 5000; // 20日日均成交额<5000万 视为低流动性
private static final double ILLIQUID_MAX_POSITION_PCT = 0.03;   // 低流动性单票仓位硬上限 3%
private static final double EXCLUDE_AVG_AMOUNT_WAN = 1000;      // 日均成交<1000万 直接剔除
```

**B. 新增方法（复用 jdbcTemplate 查 CH）**
```java
public List<String> checkLiquidityCap(List<StockRecommendation> recs) {
    List<String> warnings = new ArrayList<>();
    for (StockRecommendation rec : recs) {
        String code = rec.getCode();
        try {
            // 取最近20日 avg(amount)/avg(turnover)；amount 单位千元→万元需 /10
            Map<String, Object> row = jdbcTemplate.queryForMap(
                "SELECT avg(amount) a, avg(turnover) t FROM (" +
                "SELECT amount, turnover FROM stock_daily WHERE code=? " +
                "ORDER BY trade_date DESC LIMIT 20) s", code);
            double avgAmountWan = ((Number) row.get("a")).doubleValue() / 10.0; // 千元→万元
            double avgTurnover = row.get("t") != null ? ((Number) row.get("t")).doubleValue() : 0;
            double pos = rec.getSuggestedPositionPct() != null ? rec.getSuggestedPositionPct() : 0.05;
            if (avgAmountWan < EXCLUDE_AVG_AMOUNT_WAN) {
                rec.setSuggestedPositionPct(0.0); // 直接剔除
                warnings.add(code + " 流动性极低(日均" + String.format("%.0f", avgAmountWan) + "万)已剔除");
            } else if (avgAmountWan < ILLIQUID_AVG_AMOUNT_WAN || avgTurnover < ILLIQUID_AVG_TURNOVER_PCT) {
                double capped = Math.min(pos, ILLIQUID_MAX_POSITION_PCT);
                rec.setSuggestedPositionPct(capped);
                if (capped < pos) warnings.add(code + " 低流动性，仓位 " +
                    String.format("%.0f%%", pos*100) + "→" + String.format("%.0f%%", capped*100));
            }
        } catch (Exception e) {
            log.warn("流动性检查失败: {} {}", code, e.getMessage());
        }
    }
    return warnings;
}
```
> 注：`stock_daily.turnover` 列名需确认（CH 表结构见 `stock-service/sql/ch.sql`）；若无 turnover 列，改用 `amount` 单一维度即可。

**C. 接入每日风险入口**
```java
// runFullPortfolioRiskCheck 内，其它 check 之后追加
List<String> liqWarnings = checkLiquidityCap(allRecommendations);
result.put("liquidityWarnings", liqWarnings);
```

### 2.3 验证
- 低流动性小盘（如日均成交 800 万）→ 组合层自动剔除，不依赖前端质量分。
- 中等流动性（日均 3000 万）→ 仓位从 5% 砍到 3%。
- 与选股质量分互补：质量分是"打分排序"，本项是"硬上限/剔除"，双保险。

### 2.4 风险/回滚
- 阈值偏严会误伤部分小盘 alpha。建议先在**观察模式**（只记 warning 不真正改仓位）跑一周，确认剔除名单合理后再切"生效"。
- 回滚：注释掉 `runFullPortfolioRiskCheck` 里的调用即可。
