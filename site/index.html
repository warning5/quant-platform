EXTENSIBILITY

不是黑盒，扩展点全部开放

因子、策略、数据源、归因四类能力都有明确的扩展契约：写一段脚本或加一条配置即可接入，不必改动主干代码。

01
🧩

因子扩展 · 四种类型

内置 Java 因子之外，脚本因子、组合因子、形态因子都能在系统里直接新增，页面上配完即可参与计算。

  • 类型BUILTIN 内置 · SCRIPTED 脚本 · COMPOSITE 组合 · PATTERN 形态
  • 承载脚本文本存于 factor_definition.script_code，组合因子用 factor_config_json 复用既有因子
  • 引擎ScriptedFactorEngine 执行，由 FactorComputeEngine 统一分发
  • 安全Groovy 沙箱：源码预检 + AST 白名单 + 30 秒超时熔断
02
🧠

策略扩展 · Groovy 即策略

策略不是写死的参数组合，而是一段可读、可调、可直接回测的脚本，在线编辑后立刻验证。

  • 契约返回 Map<String,Number>，股票代码 → 目标权重
  • 上下文bars · symbols · factorValues · indexBars · industryMap
  • 执行BacktestScoring 注入绑定变量后调用，60 秒沙箱超时
  • 入口策略编辑页在线编写，脚本存于 strategy_definition.script_code
// symbols: 候选股票列表  factorValues: 因子值
return symbols.findAll { factorValues.get(it)?.get("VAL_PB") < 2 }
              .collectEntries { [(it): 1.0d / symbols.size()] }
03
🔌

数据接入 · 脚本与调度解耦

采集脚本与调度规则分离，接一个新数据源只需加脚本 + 配一条 cron，主链路零改动。

  • 脚本update_*.py 命名统一，数据源抽在 data_provider/ 抽象层
  • 调度data_schedule_config 支持自定义 cron_expression，category=CUSTOM
  • 编排data_task_dependency 声明上下游与延迟秒数，支持多上游门控
  • 触发ScheduleService 自动装载 cron，页面可启停与手动执行
04
🔗

归因与外部集成

归因实现是独立 Service，API 层开箱可用；推荐结果可被外部系统按 token 直接消费。

  • 归因BrinsonAttributionService · FactorStyleAttributionService（含 FF3）
  • 扩展新增一种归因：加 compute* 方法 + 一个 Controller 端点
  • 接口OpenAPI 文档 /api/swagger-ui.html，/api/v3/api-docs
  • 推送STOMP WebSocket /ws 与 /ws-native，回测进度实时推送
  • 取数GET /recommendations/latest 拉取每日推荐结果
Groovy 沙箱白名单 脚本热加载，无需重启 cron 自定义任务 springdoc OpenAPI Sa-Token 权限控制 MySQL / ClickHouse 双数据源

四步跑起来

详细的每一步说明、参数含义与排错指南，见《使用手册》与仓库 docs/quickstart.md。

初始化数据库

导入 stock-service/sql/stock.sql（MySQL）与 ch.sql（ClickHouse），应用启动不执行 DDL。

启动后端

JDK 21 + Maven 3.8 打包后运行 stock-service，接口前缀 /api，端口 8080。

启动前端

Node 18+，npm install && npm start，访问 http://localhost:3000。

采集数据并计算

在「数据更新」页采集行情，再执行因子计算与推荐任务，即可看到每日选股结果。

# 1. 后端
mvn clean package -DskipTests
java -jar stock-service/target/stock-service-1.0.0.jar

# 2. 前端
cd frontend && npm install && npm start

# 3. 数据库（仅结构，不含数据）
mysql -u root -p stock < stock-service/sql/stock.sql
